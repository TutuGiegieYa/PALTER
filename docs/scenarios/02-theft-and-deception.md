# Theft and Deception Scenario

Status: Distinct custody, ownership, transfer and recovery runtime implemented.

Last updated: 2026-11-05.

## Current Runtime

The initial disappearance is fixed background: the actual custodian differs from the rightful owner. Ownership, custody and handover records can be inspected independently. Actual co-located transfer returns the item; claiming to have returned it does not. Each role needs an active contribution plus the collective return, and separately protects or exposes a designated private record. Shared actions include object handling and an attributed handwritten claim document; arbitrary handwriting imitation and guaranteed deception are not supported.

See [runtime and verification](../17-complete-playable-runtime.md). Tests exercise both successful effects and failed/partial goals. The setting and broader ending alternatives below are retained as design material; this section defines the implemented policy.


Category proposal: Mystery and Investigation.

## Premise and Initial Information

During an exhibition or handover, a disputed valuable object is no longer where participants expect it. Ownership, custody, and the legitimacy of earlier agreements may differ.

Initial memories describe deliveries, private transactions, access, and prior promises. Relationships include debts, rival claims, and personal loyalties. The story must establish whether the initial disappearance is fixed background or an opening action sequence.

## Objectives and Actions

Possible objectives include recovering the object, establishing ownership, preserving a transaction secret, protecting a courier, or completing a handover.

Characters can compare records, inspect permitted locations, negotiate returns, observe a route, guard a container, or transfer an object under actual access conditions.

### Free-Action Illustration: A Forged Note

Under the proposed [shared action policy](../04-world-events-and-actions.md), a character might try to write a false collection note and leave it where another participant can find it. This is a scenario example, not an adopted universal forgery mechanic.

Separate producing the note, placing or delivering it, and its recipient's later interpretation. Check actual access to materials, any handwriting knowledge needed for the attempted imitation, custody, time, and observation conditions. The note can contain a false assertion without rewriting the actual collection history. Producing a convincing-looking object does not compel another human or AI character to believe it.

If an authorized plan includes placement, validate that step when it becomes due. If the location is inaccessible, do not automatically choose a new target or enlist an accomplice for the human. Possible grounded outcomes include successful placement, interruption, a recognizable imitation, or the note remaining unread. Trace and detection rules need explicit scenario support, and feedback must not reveal hidden observers.

## Events and Constraints

An appraisal visit, delayed courier, announced departure, changing access, or public inventory creates action opportunities at any appropriate time.

Track actual custody and exchanges. A missing object does not automatically imply a particular criminal role or a single culprit. Those facts must follow the scenario setup and actual actions.

## Ending Proposals

Recovery by the rightful claimant; recovery by a mistaken claimant; an agreed settlement; concealed ownership history; an unresolved disappearance; or recovery that destroys an alliance.

## Broader Design Questions

Opening timing, ownership rules, object verification, exchange mechanics, deadlines, and which facts are public in the introduction.
